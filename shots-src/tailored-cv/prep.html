T-007 · design asked 2×

How would you make an event consumer idempotent?

Why it's likely: "event-driven architectures" is a core requirement, and it came up in two of your last three technical rounds.

❌ 28 Oct · technical · jumped to tools, no pattern ⚠️ 14 Oct · technical · right idea, no example

Best answer (~30 s)

"Assume every message can arrive twice. Each event carries an ID; the consumer records it in the same transaction as the write and skips IDs it has seen. At Larkspur that kept 3M events a day on SQS consistent through retries."
  • Pattern first: dedup key + transactional write
  • Then the example and its numbers
Honesty: you haven't used Kafka. Anchor the answer on SQS/SNS and say how it would map.
